# ES2 单人 TUI 完整移植计划

## 1. 目标与“100%”定义

源基线固定为 `es2-utf8` 仓库提交 `87bba6b`。完成度以该提交为准，不随上游变化漂移。

“100% 移植”表示：原作所有面向普通玩家且能在单人游戏中成立的地点、NPC、物品、武学、战斗、任务、经济和世界事件，都在 TUI 中具有可操作的等价行为，并通过自动测试或人工验收。仅导入名称和描述不算行为完成。

以下多人或运维功能不直接移植，但必须有明确处置结果：

| 原功能 | 单人版处置 |
| --- | --- |
| 登录、账号、密码、网络会话 | 删除，由单一本地存档取代 |
| `say/tell/whisper/shout/channel` | NPC 对话、环境事件和日志取代 |
| 队伍、玩家师徒、玩家帮派 | NPC 同伴、NPC 师承和剧情声望取代 |
| PVP、跨服、邮件 | 排除；相关奖励移入挑战或委托 |
| 巫师、管理员、在线编辑器 | 排除运行时功能，保留离线内容工具 |
| WebMUD、Telnet 代理 | 排除，由 Ratatui/Crossterm 取代 |
| 重启、清理、网络守护进程 | 排除；需要的时间逻辑进入本地世界时钟 |

排除项必须登记原因和替代方案。未经登记的缺失内容视为未完成。

## 3. 迁移原则

1. **稳定 ID**：内容使用 `/d/...` 派生的字符串 ID，存档不依赖 Rust 枚举序号。
2. **数据与规则分离**：名称、描述、出口、数值和掉落进入数据文件；战斗、任务和命令行为进入 Rust 规则模块。
3. **保留来源**：每个迁移条目记录原 LPC 路径和源提交，能够追溯差异。
4. **先等价后改编**：先记录原行为，再定义单人替代；不静默删减。
5. **可重复导入**：静态 LPC 字段由工具抽取，手工覆盖与生成文件分离。
6. **存档可升级**：每次模型变更提供旧版本迁移，不能直接让已有存档崩溃。
7. **完成度不按代码行计算**：只有结构、行为、验证三个状态全部完成才算 `done`。

## 4. 内容状态模型

每个条目使用以下状态：

- `discovered`：已在源仓库发现。
- `structured`：静态字段已导入，引用已解析。
- `implemented`：动态行为已有单人版实现。
- `verified`：自动测试通过并完成人工玩法检查。
- `excluded`：已记录排除理由和替代方案。
- `blocked`：依赖尚未迁移或源行为无法确定。

区域完成条件：区域内所有条目均为 `verified` 或 `excluded`，且不存在无法到达的房间、悬空出口、无效物品引用和不可完成任务。

## 6. 测试策略

- **内容测试**：ID 唯一、出口目标存在、对象/技能引用有效、区域可达。
- **规则测试**：战斗、经济、状态、学习条件和任务状态机。
- **回归场景**：以固定随机种子运行关键任务和门派成长流程。
- **存档测试**：每个 schema 版本都能升级到当前版本。
- **TUI 测试**：58×20、80×24、120×30；普通、战斗、弹窗和长文本状态。
- **人工验收**：每个区域至少完成一次从入口到主要剧情终点的游玩记录。
